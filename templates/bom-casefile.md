# BOM 校验 AI 员工
> 用于 BOM 校验与工程审查的多 Agent AI 员工。

**领域:** 制造工程  ·  **状态:** 公开参考案例

## 业务问题

工程师需要对照材料标准、参数限值与设计规则，手工校验物料清单（BOM）。一张 BOM 可能包含上千个行项目，每一项都要对照正确的标准与正确的参数窗口进行检查。

### 为什么现有流程会失败

这是大规模下的重复性检索与比对工作。人会疲劳，不同工程师的覆盖度不一致，而且因为审查发生在周期后段，给设计的反馈很慢。

## 我如何重构这项工作

不再让一名工程师端到端地做“检索—比对—报告”，而是把工作重构为一组协同的 Agent：规划器把 BOM 拆成可检查单元，检索器拉取适用的标准与材料数据，执行器跑比对，审查器在人工签字前对输出把关。

### AI 员工定义

- **角色:** BOM 校验工程师
- **职责:**
  - 在问题流入生产前发现 BOM 异常
  - 为每条发现引用其适用的标准条款
  - 产出人工可信、可直接审查的报告
- **任务:**
  - 把 BOM 解析为可检查项
  - 检索适用的标准与材料规格
  - 对照限值与规则比对参数
  - 发现风险与不一致
  - 起草结构化的审查报告

## 业务语义

语义层让一条发现可被审计。没有它，Agent 只能说“参数超范围”，却无法证明违反了哪条规则。语义把一个猜测变成一条带证据的断言。

| 层 | 捕获什么 |
|---|---|
| 本体 Ontology | BOM 实体、材料类别、标准引用及其关系 |
| 规则 Rules | 参数限值、兼容性约束、设计意图 |
| 证据映射 Evidence mapping | 每条发现都链到证明其成立的精确标准条款 |

## Agent 架构

一个规划器协调三个知识源与一个执行器，再由审查器对输出把关。最终报告由人工批准。

| Agent | 角色 | 输入 | 输出 |
|---|---|---|---|
| 规划器 Planner | 把 BOM 审查拆成子任务 | BOM | 任务计划 |
| 标准检索器 Standards Retriever | 查找适用的标准 | 零件规格 | 标准条款 |
| 材料检索器 Materials Retriever | 获取材料规格 | 材料编号 | 材料数据 |
| 规则引擎 Rules Engine | 应用校验规则 | 规格 + 规则 | 逐项通过/失败 |
| 执行器 Executor | 执行比对 | 计划 + 检索数据 | 发现 |
| 审查器 Reviewer | 检查发现质量 | 发现 | 已审查发现 |

**工作流:** 规划器 → 标准+材料检索器 → 执行器 → 审查器 → 人工批准 → 最终报告

## 约束框架

约束框架限定 Agent 能做什么，并强制在任何断言之前先有证据。

- **上下文:** BOM + 标准库 + 材料数据库
- **工具:** 标准检索、材料查询、规则求值
- **规则:** 每条发现必须引用标准条款；无证据不得断言
- **护栏:** 对源系统只读；绝不自动修改 BOM
- **人在环:** 高级工程师在报告到达设计之前批准

## 评估

由人工工程师与 AI 员工分别审查抽样 BOM，比较发现的覆盖率与误报率。

| 指标 | 目标 |
|---|---|
| 发现召回率 | 对比人工 ≥ 90% |
| 误报率 | < 5% |

**人工复核:** 高级工程师对每份报告签字确认
